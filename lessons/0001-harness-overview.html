LLM Agent 与 Harness 工程 · 第 01 课

Harness：模型之外的那半个产品

写给非工程背景的产品人：一个类比、一张组件清单、三个"为什么现在必须懂它"的理由。读完本课，你看 AI 编程/办公产品的眼光会不一样。

0. 一句话定义

Harness（直译"挽具/线束"）指包裹在 LLM 模型外面的那一整套工程系统——它负责接收输入、组织上下文、调用工具、管理权限、循环执行任务，最后把结果交回给用户。模型本身只是"输入文字 → 输出文字"的大脑，Harness 才是让它干活的身体。

1. 一个类比

把大模型想象成一匹力气很大但看不见路的马：

  • 模型：马——有原始能力，但不知道目的地在哪
  • Harness：缰绳 + 马鞍 + 马车的整套装置——决定往哪走、能走多快、拉什么货、何时停
  • 最终产品：把你送到目的地的马车
关键洞察同一匹马（同一个模型），配上不同质量的挽具，效果天差地别。这就是为什么各家 AI 产品体验差异巨大——很多时候差的不是模型，是 Harness。

2. Harness 的七个组件

组件职责产品经理视角的问题
系统提示词定义 Agent 的角色与行为规范我们的 Agent 应该多主动？多保守？
上下文管理决定模型每次"看到"哪些信息窗口有限，什么该进、什么该裁？
工具层让模型能读文件、执行命令、上网给多少工具？每个工具怎么描述？
Agent 循环思考 → 调工具 → 看结果 → 再思考最多循环几轮？失败了怎么办？
权限与安全哪些操作要用户确认删除文件要不要弹窗？信任设计的核心
记忆系统跨会话保存偏好与项目知识用户不想重复交代背景
结果呈现diff 展示、引用、进度反馈用户怎么验证 Agent 干得对？

3. 为什么这个词现在这么火

  1. 模型趋同，Harness 成为差异化主战场——大家都能接顶级模型，产品好坏越来越取决于 Harness 工程质量。
  2. Harness Engineering 正在成为新工种——提升 Agent 效果的关键往往不是换模型，而是优化上下文组织、工具设计与循环控制。
  3. 它重新定义了"提示词工程"——从写一段话，升级为设计提示词、工具、上下文、反馈回路共同构成的系统。
