1. 十款产品 × 六维度矩阵

六个维度的选取逻辑：①服务对象 ②执行位置 ③循环透明度 ④交付形态 ⑤并行能力 ⑥生态绑定——分别回答"给谁用、在哪跑、看不看得见、给你什么、能同时干几件、被什么锁定"。

2. 维度④深挖：交付形态是产品定位的指纹

六个维度里，"交付形态"最能区分产品哲学：

  • diff / PR 系（Cursor、Claude Code、Codex、Qoder）：交付的是"变更"，天然需要评审环节——所以这类产品的 UX 核心是评审体验（diff 展示、一键回滚）。
  • 成品文件系（千问办公、WorkBuddy、Manus、QoderWork）：交付的是"可直接用的东西"，用户不评审过程只看结果——UX 核心是成果预览与迭代（"再改一版"按钮）。
  • 对话+代办系（ChatGPT、Claude）：交付混合体，既回答问题又帮你操作——UX 核心是意图切换的顺滑度。

3. 新维度发现：组织角色阶梯

把十款产品按"它假装是组织里的什么角色"排列，会得到一条清晰的进化阶梯：

角色隐喻产品人的动作
结对同事Cursor你写一行它补一行，随时接手
可委托的工程师Claude Code、Qoder交代任务，盯过程，把关结果
外包团队Codex 云端、Manus发需求，等交付，验收成果
数字员工WorkBuddy 企业版、QoderWake设岗位、定职责、看周报

这条阶梯就是 2025→2026 行业叙事的主线：从"工具"到"队友"再到"员工"。角色越往上，pass^k 压力越大（员工要每天都靠谱）、评估越难、信任设计越重要——前四课的概念全部在这里收拢。

4. 矩阵里的三个新洞察

  1. 生态列几乎人人有，但锁定方式分两类：开发者产品靠习惯与标准（IDE 键位、MCP、Skills 开放格式），办公产品靠组织关系（钉钉/腾讯的企业入口）。前者可迁移、后者难迁移——这决定了各自的获客与流失逻辑。
  2. 编程四兄弟的"执行位置"正在分化为本地与云端两派：本地派（Cursor/Claude Code/Qoder）卖控制感与隐私，云端派（Codex）卖并行与甩手。Qoder 两头都占（IDE + 云端 Quest），是矩阵里唯一的双栖者。
  3. 横向交付阵营高度拥挤（Manus、千问办公、WorkBuddy、QoderWork 四款），差异化只剩三个抓手：生态绑定深度、技能资产积累、垂直岗位套件（QoderWork 的设计/幻灯片/写作三套件就是往这个方向走）。纯"通用代办"很快会同质化。

5. 对练题（升级版）

  1. 把你自己团队正在做的（或将要做的）AI 功能放进矩阵：六格分别填什么？哪一格最难填？难填的那格就是你的产品风险。
  2. 组织角色阶梯上，"数字员工"比"外包团队"多承担了什么？这要求 Harness 增加哪些组件？（提示：记忆、定时任务、身份与权限）
