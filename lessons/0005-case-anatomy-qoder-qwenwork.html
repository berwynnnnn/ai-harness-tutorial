LLM Agent 与 Harness 工程 · 案例课 05（智慧阶段）

解剖练习：Qoder 与千问办公都算 Harness/Agent 产品吗？

主线四课讲完了"是什么"，案例课练的是"拿来用"——用四课框架解剖两个真实产品。结论先行：都算，但它们是两种不同的物种。

前置知识：全部四课

1. 判定：都算，判据是什么

用 Anthropic 的定义：Agent = LLM 在循环中自主使用工具。两者都有工具层、都多步骤执行、都修改环境状态，故都是 harness/agent 产品。形态差异：

  • Qoder：垂直领域的深 Harness（编程 Agent），面向专业用户，暴露执行过程
  • 千问办公：横向任务交付平台（办公 Agent 集合），面向普通用户，隐藏执行过程、只给交付物

4. 三个 PM 级洞察

  1. 透明度光谱：Qoder 暴露循环（控制感、可审计，开发者需要）；千问办公隐藏循环（省心，办公用户需要）。同一内核、两种相反的产品决策，由用户群决定。
  2. 评估难度决定进化速度：编程有免费确定性评分器（测试）；办公交付物（PPT 好不好）高度主观，只能靠 LLM judge + 人工校准。后者迭代更依赖人工评测投入。
  3. 生态是横向 Harness 的护城河：千问办公绑钉钉（IM/云盘/OA），Qoder 绑 IDE + MCP。模型谁都能接，工具生态与环境接入才抄不走。

5. 对练题

千问办公宣称"一句话完成数据分析"。用第 04 课知识回答：

  1. 面向普通用户、强调每次交付可用，它该用 pass@k 还是 pass^k 守底线？
  2. 数据分析错了但用户没发现，评估体系怎么兜底？（提示：Outcome 校验可以自动化吗？）
  3. "技能沉淀"把成功轨迹变模板——这和第 04 课的哪条路线图步骤同构？

想好答案来和老师对练。
