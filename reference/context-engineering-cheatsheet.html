上下文工程速查卡

压缩自第 03 课。日常查阅用，可打印。

核心原则

上下文工程 = 为每次推理挑出"最小的高信号 token 集合"
上下文 = 边际收益递减的稀缺资源（注意力预算），不是越大越好

两个关键概念

概念含义
上下文腐化 Context Rot上下文越长，模型召回信息能力越差；所有模型共性
注意力预算 Attention BudgetTransformer 的 n² 注意关系让长上下文摊薄注意力

组成部分的纪律

  • 系统提示词：最小起步，按失败模式增量补充，分节组织
  • 工具集：最小可用；人类分不清该用哪个 → 模型更分不清
  • 示例：少量、多样、典型，勿堆边界情况清单

获取新信息：两条路线

路线特点
预计算检索（RAG）快；可能塞入无关内容、索引过期
即时检索（just-in-time）Agent 按需探索；渐进式披露；慢但准

实践赢家：混合策略（关键信息预塞 + 其余按需探索）。

长任务三法宝

技术机制适合
压缩 Compaction摘要历史 → 新窗口续跑连续来回的任务
结构化笔记状态写进上下文外的文件，之后读回有里程碑的迭代任务
子 Agent子 Agent 深探索，只回传浓缩结论可并行的研究分析

轻量手段：工具结果清理（删深层历史里的原始工具输出）。

反方观点（Cognition）

  • 行动携带隐含决策 → 多 Agent 上下文不同步会互相矛盾
  • 顺序决策型任务用单 Agent；并行探索型任务才适合子 Agent

PM 指标

上下文利用率 · 压缩触发频率 · 压缩后续跑成功率 · 工具集规模与重叠度
