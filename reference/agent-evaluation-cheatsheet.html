Agent 评估速查卡

压缩自第 04 课。日常查阅用，可打印。

核心口诀

评结果（Outcome），别只听 Agent 说什么（Transcript）
能用代码判的，别用模型判；没有评估的团队在"盲飞"

七个术语

Task 任务有明确输入+成功标准的一个测试
Trial 尝试对一个任务的一次执行（要多跑）
Grader 评分器给表现某方面打分的逻辑
Transcript 轨迹一次尝试的完整记录
Outcome 结果环境的真实最终状态
Suite 套件围绕同一能力目标的一组任务
Eval harness端到端跑评估的基础设施

三种评分器

类型特点用法
代码快/便宜/客观，但死板首选
模型（LLM judge）灵活，需校准开放性任务；给它"可答不知道"的退路
人工金标准，贵且慢校准模型评分器、抽查

两套评估

能力评估：通过率故意从低 → 爬山的信号 → 高分后"毕业"进回归套件。
回归评估：预期 ≈100%，下降即报警。

不确定性指标

指标含义场景
pass@kk 次至少成一次；k↑ 分↑批处理/内部工具
pass^kk 次全部成功；k↑ 分↓（0.75³≈42%）面向用户的功能

路线图精华

  1. 尽早：20-50 个来自真实失败的任务
  2. 取材：手工测试 + bug 清单
  3. 任务无歧义：两位专家独立判断结论一致
  4. 评结果不评路径，别锁死工具调用顺序
  5. 部分得分体现连续谱
  6. 防作弊：通过只能靠真解决
  7. 读轨迹！没读过轨迹前不轻信分数
  8. 防饱和：100% 通过率的评估该换难题

多层防线（瑞士奶酪）

自动化评估（上线前）+ 生产监控 + A/B 测试 + 用户反馈 + 人工轨迹审阅 + 系统性人工评估。
